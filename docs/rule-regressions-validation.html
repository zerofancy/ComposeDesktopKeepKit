JNA / Logback / D-Bus 规则修复与回归验证

2026-10-16 · v0.2.5 修复；不改变已发布 v0.2.4 标签。

这批修复处理 11 项已复现的缺口：最初的 JNA GC 锚点，以及后续审计确认的 JNA 5 项、Logback 3 项、D-Bus 2 项。全部使用真实 ProGuard 收缩、优化和混淆后的程序验证；不以构建成功替代运行验证。

规则修复

范围触发条件与旧行为修复
JNA GC 生命周期Native.finalizer 是只写不读的静态锚点。字段被裁剪后，GC 提前调用 Native.dispose()；Linux 下仍在使用的 libudev 函数指针导致 SIGSEGV。保留该字段。每个 JVM 中执行 200 次 GC；Linux 同时创建、释放 libudev 上下文。先检查 jna.loaded，让负例以明确断言失败，避免故意制造原生段错误。
Structure(Pointer)只有 Pointer 构造器的 Structure 无法被 Structure.newInstance(type,pointer) 创建。保留 public Pointer 构造器，继续保留既有的无参构造器和字段保护。
NativeMapped 枚举defaultValue() 调用 Class.getEnumConstants()[0]；values() 被裁剪导致 NPE。按 NativeMapped 角色保留枚举 values()。
直接映射的方法名Native.register(Class,library) 按 Java native 方法名查找 C 符号；改名后 UnsatisfiedLinkError。按 native 方法角色保留类、方法及描述符名称；不用全包 keep，未使用的 native 方法仍可裁剪。
直接映射的调用栈5.15/5.16 的隐式 register(String) 根据固定栈深识别调用类；优化后识别了错误的类。只限制 Native.register / unregister / getCallingClass 的优化，允许裁剪和改名。
ByReference 诊断自定义子类仅供 toString() 反射的 getValue() 丢失，输出 Contract violated。保留 ByReference 子类的 getValue()。测试自定义子类，避免内置 IntByReference 自己覆盖 toString() 掩盖问题。
Logback FilterReplyXML onMatch/onMismatch 经 Enum.valueOf 转换，values() 被裁剪。保留 FilterReply.values()。
Logback LevelLevelFilter 的 level 属性依赖反射 valueOf(String)，与 root logger 的专用 level 配置路径不同。在 classic 规则中保留 Level.valueOf(String)。
Logback Durationtimeout、checkIncrement 等 Duration 属性无法按字符串转换。保留 Duration.valueOf(String)，补齐 FileSize 之外的标准类型。
D-Bus 属性注解读取 @DBusProperty 的枚举默认值时出现 AnnotationFormatError。精确保留 Access / EmitChangeSignal 的 values() 和常量字段名。
D-Bus 扩展注解通过 getDeclaredAnnotations() 才发现的注解被移除，introspection XML 静默丢失内容。按 @DBusInterfaceName 角色保留 annotation 类型和成员，不仅保留成员。

正式回归样例

Gradle 样例仅使用 Java 插件和 ProGuard 7.7.0，通过 Gradle 解析依赖及 JDK 21，不依赖本机缓存目录。JNA、Logback 和 D-Bus 分别只直接引入自身目标库，其余来自正常传递依赖。没有引入 Compose 默认规则来保护这些入口。

  • JNA：5.15.0、JPMS 5.16.0、5.19.1。每个版本 8 个场景，分别运行未收缩控制组和收缩正例；6 种逐规则负例，5.19.1 不执行只在旧版复现的调用栈负例。
  • Logback：1.5.16、1.6.5。每个版本执行枚举、Level、Duration 和真实 XML LevelFilter 4 个场景；XML 同时断言匹配 INFO 返回 ACCEPT、不匹配 DEBUG 返回 DENY。另逐项移除 3 个转换保护运行负例。
  • D-Bus：5.2.0。属性和扩展注解分别验证。扩展注解负例继续保留属性枚举保护，确保测试的是静默内容丢失，而非前置注解异常。
  • 每个负例仅移除一个保护，并核对该场景的具体运行异常。规则定位不再匹配时直接构建失败，不允许“负例”悄悄退化为正例。
  • 每个收缩产物要求目标依赖确实存在类改名，并确认 UnusedRegressionMarker 被裁剪。额外保留强制 GC 后的 callback 和共享内存回归。
  • 普通 native 直接映射按操作系统选用 getpid / _getpid。libudev 仅在 Linux 实际调用；其他平台仍执行通用 GC 生命周期断言。JPMS 发行物在 classpath 验证，不声明 module-path 覆盖。

完整新增矩阵为 93 个运行断言：34 个未收缩控制组、34 个收缩正例、25 个预期运行失败反例。驱动脚本只在所有实际执行的断言通过时退出 0。

python3 samples/rule-regressions/verify.py
# 定向排查（不会读取之前的成功结果）：
python3 samples/rule-regressions/verify.py --family jna
python3 samples/rule-regressions/verify.py --family logback
python3 samples/rule-regressions/verify.py --family dbus

日志和结果位于 samples/rule-regressions/build/verification；每份产物旁另有 config.pro、rules.pro、mapping.txt、usage.txt 和 runtime.json。

范围边界

新回归覆盖固定版本的具体框架合同，不能证明所有 API、所有旧版本和所有应用都无需补规则。Logback 任意业务类型的 XML 反射仍需要应用规则；JNA 普通父接口原生符号名仍应遵循 Library 继承约定。发布状态见 v0.2.5 发布验证。本轮不替换消费项目安装包，也不声明 GUI、模块化 JPMS 或真实 D-Bus 服务连接验证。

上游依据：JNA 5.19.1、JNA 5.15.0 Native、Logback 转换入口、D-Bus ExportedObject。
