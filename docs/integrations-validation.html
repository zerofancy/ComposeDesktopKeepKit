保护范围

  • Retrofit：服务方法注解、泛型签名及代理接口；不保留业务包。
  • Serialization：Companion / object 的 serializer 入口及 descriptor 优化契约。模型字段、模型类名、整个 serializer 类不做全量保护。named companion 字段、descriptor 字段仍允许混淆。
  • SLF4J / Logback：SPI 名称和构造入口；XML 标准扩展角色、ContextAware JavaBean 属性及 ProcessingPhase 枚举反射入口。
  • JNA：JNI 固定名称、少量固定字段和回调；Library 接口方法、Structure 字段与构造入口、Callback 入口、嵌套结构体 OPTIONS 的 enclosing 属性。JNA Platform 另补 LibCAPI 原生函数名称。
  • D-Bus：总线接口名称和方法、泛型与注解、结构字段、信号 / 异常构造入口及 native-unixsocket SPI。
  • SQLite：JDBC SPI、NativeDB.c 指定的 JNI 类和成员、四个配置枚举的 values() 入口；SLF4J 缺失时使用 JDK 日志。
  • Llamatik：Bridge native 名称、GenStream 固定回调名称。其他普通方法、LlamaSession 等不做全包 keep。
  • OkHttp 5：后缀数据库资源名称、可选平台 / TLS / GraalVM 引用；根组件与 JVM 坐标共享规则并去重。

单独引入揭示的问题

综合依赖曾相互提供 Signature、Android、GraalVM 等保护。隔离测试分别发现并补齐 Retrofit 的 Android 可选引用、OkHttp 5 的 GraalVM 可选引用、SQLite 的可选 SLF4J 引用，以及 JNA Platform 的 LibCAPI 继承方法名称。

Compose 1.9.3 默认包含较宽的 serialization keep，直接禁用插件规则不足以构成反例。因此 core 与 JSON 分别使用独立 ProGuard fixture，仅注入 serialization.pro，验证默认 Companion、named companion、object 和真实 JSON 解码。

运行边界

只记录本机 Linux 验证，不声明 Windows / macOS 已通过。JNA 测试真实 libc、结构体、回调及继承接口；D-Bus 测试接口反射和 transport provider 发现，不连接外部会话总线。FileKit 验证真实 JNA 初始化、D-Bus SPI 和 portal 接口，不弹出文件选择窗口。Llamatik 加载真实原生库并调用 shutdown，另验证回调名称；不下载模型，不声明生成、语音、图像或流式推理已经验证。

Logback core 单独验证扩展类反射构造与 JavaBean 属性，classic 验证 XML encoder/appender 和自定义 Configurator SPI。XML 中任意其他类型仍需用户规则。JNA 的用户原生接口与父接口应继承 Library；其他普通父接口的原生方法需自行保留名称。

Retrofit converter 本身只传递引入 serialization core，不包含 JSON。隔离样例提供基于 core 的 StringFormat，验证真实请求和响应转换；没有额外引入 JSON。SQLDelight 使用真实 JdbcSqliteDriver 执行内存查询。
