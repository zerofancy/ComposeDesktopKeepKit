FloatClock：DataStore 与 OSHI Release 验证

验证日期：2026-10-12。新增内容由 v0.2.4 提供。v0.2.3 不包含这两份规则。

DataStore 配置持久化、独立 Okio 存储和 OSHI 原生硬件/网卡访问在启用优化与混淆的 Release JAR 中通过；禁用新增规则的两组反例在运行阶段失败。

规则范围

依赖坐标与版本保护内容
androidx.datastore:datastore-preferences-core-jvm:1.1.7复用上游 consumer rule，仅保留 shaded GeneratedMessageLite 子类的字段。通过实际解析到的 preferences-core-jvm 自动保护传递的 preferences-proto。
com.github.oshi:oshi-core:6.6.5仅保留 OSHI 枚举的 values() 入口，供 Class.getEnumConstants()、EnumSet 与 WMI/PDH/proc 通用辅助函数反射调用。枚举类与字段仍可裁剪、改名。

DataStore core / core-okio 不新增全包 keep；Okio 和 Coroutines 继续匹配已有规则。OSHI 的 Library 接口、Structure 字段与原生入口继续由传递 JNA / JNA Platform 规则保护。未为 datastore-preferences-proto 单独注册适配器：它由 preferences-core 的正常传递路径覆盖。

固定基线

macOS arm64；JDK 21.0.12.1；Gradle 8.14.3；Kotlin 2.2.0；Compose 1.8.2；ProGuard 7.7.0。依赖版本：DataStore 1.1.7、Okio 3.4.0、Coroutines core 1.10.2、OSHI 6.6.5、JNA / JNA Platform 5.15.0、SLF4J 2.0.19。

样例与 FloatClock 使用相同的 Compose、Kotlin 和目标库版本，Gradle 沿用 KeepKit wrapper。每个场景除 Compose Desktop 基线外，只直接声明一个目标库；版本约束只对齐已存在的传递依赖。每个场景通过本地 includeBuild 应用真正的 KeepKit 插件，由最终依赖坐标生成规则，没有手动包含新增片段。

独立正反例

场景检查内容结果
datastore-positivePreferences 写入 clock-format，关闭并等待 scope 清理后，重新打开同一文件读取原值。通过
datastore-okio-positive仅直接引入 core-okio-jvm，使用自定义字符串 Serializer 完成持久化、关闭和重新读取。通过；无需新增全包规则
oshi-positiveWMI 查询字符串精确断言，PDH / Linux proc 枚举反射；真实内存、CPU、进程 ID、网卡名称、计数更新与 Java 网络接口访问。通过；本机枚举到 8 个网络接口
datastore-negative只禁用 preferences-core-jvm 适配器，保留其他正常传递规则。构建通过，runRelease 失败：Field value_ … not found. Known fields …
oshi-negative只禁用 OSHI 适配器，保留 JNA 与其他传递规则。构建通过，runRelease 失败：WMI queryToString 中枚举反射返回 null，触发 NullPointerException。

验证脚本要求正例输出 PASS、依赖类确实发生重命名，并确认故意不被引用的 UnusedSmokeMarker 被裁剪。反例必须在 runRelease 失败并出现对应诊断，下载、编译或 ProGuard 构建失败不算反例通过。优化与混淆均显式开启。

复现与证据

JAVA_HOME=/path/to/jdk21 python3 samples/floatclock-dependencies/verify.py
JAVA_HOME=/path/to/jdk21 ./gradlew check
JAVA_HOME=/path/to/jdk21 ./gradlew -p samples/coil-desktop runRelease
JAVA_HOME=/path/to/jdk21 ./gradlew -p samples/coil-kmp runRelease

结果与日志位于 samples/floatclock-dependencies/build/verification/：results.json、各场景日志、mapping.txt 和 usage.txt。./gradlew check 与两个 Coil Release 回归样例均通过。

远端发布验证

JitPack v0.2.4 的真实远端插件同样通过全部五项正反例，不使用 includeBuild 或 mavenLocal。运行脚本时添加 --remote-version v0.2.4；发布产物核对与消费证据见 v0.2.4 发布验证。

验证边界

这次验证覆盖独立依赖的真实收缩运行，不代表 FloatClock 整个 GUI 或安装包已经验收。未修改 FloatClock 的构建配置或原有规则。macOS 上执行了真实 OSHI 原生调用；Windows WMI / PDH 枚举反射与 Linux proc 枚举合同在本机验证，Windows COM、PDH 原生计数和 Linux 原生调用尚未在对应系统上执行。应用自有 MacOSWindowBridge JNI 以及项目特定 Compose 规则仍需保留并另行验证。

来源

DataStore 字段规则来自 1.1.7 发布 JAR 内的 consumer rules（Apache-2.0）；OSHI 规则依据 6.6.5 固定版本源码（MIT）的枚举反射合同编写，许可证说明已补入 NOTICE。
