可信基线与漏测保护

push 从同分支最近一次成功且属于当前提交历史的 CI 提交计算累计差异；不直接信任 push.before。失败、取消或尚未完成的测试不会推进成功基线，因此“改规则失败后只改文档”仍会重测此前未通过的规则。PR 从目标分支的成功祖先提交比较到当前合并提交，包含 PR 和目标分支尚未验证的累计变化。找不到这样的基线、发生历史改写或访问 API 出错时回退全量。

Git diff 禁用重命名折叠，同时检查移动前后的路径。选择清单列出传递规则输入，Compose fixture 运行时复制实际生成的规则报告；若清单漏记了实际解析出的规则，验证直接失败。新增场景必须同步维护 scripts/ci/coverage.py，选择器回归检查场景名称与三个验证脚本的完整清单一致。

每轮选择结果展示在 Actions job summary，并作为 ci-selection 产物保存；所选场景保留结果 JSON、收缩配置、mapping、usage 和日志。CI result 汇总选择器及所有所选任务，失败或取消不会被汇报为成功；无须运行的任务可以正常跳过。

手动全量与本地复现

Actions → CI → Run workflow 始终全量，适合发布前、运行环境更新后及需要主动复查时使用。现有的本地验证脚本不传筛选参数仍执行全部场景，不依赖 CI 成功缓存。

python3 -m unittest discover -s scripts/ci -p 'test_*.py' -v
python3 scripts/ci/plan.py --base <成功提交 SHA>
python3 scripts/ci/plan.py --full
python3 samples/integrations/verify.py --only jna-positive jna-negative restored-positive
python3 samples/floatclock-dependencies/verify.py --only oshi-positive oshi-negative
python3 samples/kzagent-dependencies/verify.py --list-cases

本地 plan 的 head 默认为已提交的 HEAD；--base 应指向实际成功的提交。该入口用于检查计划，GitHub 上的自动基线通过工作流成功记录取得。
