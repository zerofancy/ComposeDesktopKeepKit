Logback 旧版与滚动日志规则修复验证

2026-10-11 · v0.2.2 修复。既有 v0.2.1 不包含本次修复。

复现与修复

原目录只登记 1.6.5，旧版 1.5.16 因向上选择使用同一片段。独立引入 1.5.16、无 Janino 时，ProGuard 报 PropertyEvalScriptBuilder 对 ClassBodyEvaluator 和 CompileException 的缺失引用。新增 1.5.16 core / classic 基线，仅旧版 core 额外加载 logback-janino.pro；条件脚本仍要求应用自行引入 Janino，警告抑制不提供该功能。

原规则加上述两条警告抑制后仍运行失败：Joran 无法通过反射找到 FileSize.valueOf(String)，maxFileSize / totalSizeCap 转换失败，RollingFileAppender 未启动。开启混淆和禁用混淆均已复现。修复只保留 FileSize 的静态 valueOf(String)，不保留整个包或关闭优化。

正式隔离样例

每个场景只直接引入一个 Logback core 或 classic（另有 Compose Desktop 基线），其余库通过正常传递依赖解析。core 验证反射创建 ConsoleAppender 和 JavaBean setter；classic 验证自定义 Configurator SPI、隐式 PatternLayoutEncoder、ConsoleAppender、SizeAndTimeBasedRollingPolicy、maxFileSize / totalSizeCap 配置、文件写入和配置扫描任务注册，并断言不存在 Logback ERROR 状态。

XML 复制到独立临时文件后通过 logback.configurationFile 加载，避免 JAR 内不可监听资源导致扫描检查失效。样例结束停止 LoggerContext 并删除临时文件。不声明已验证达到尺寸后的归档、实际重载触发或 Janino 条件脚本执行。

环境：Windows x64、Microsoft JDK 21.0.12、Gradle 8.14.3、Kotlin 2.4.21、Compose 1.9.3、ProGuard 7.7.0。默认开启优化和混淆，另测试 1.5.16 禁用混淆。此次未在 Linux/macOS 运行。
