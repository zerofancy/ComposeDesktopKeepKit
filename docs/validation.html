验证结果
./gradlew check9 项测试通过（6 项规则单测、3 项 TestKit）；插件任务属性校验通过。
JVM / KMP runRelease两个样例在真实 ProGuard 7.7.0 收缩 JAR 上运行，优化和混淆均启用；HTTP PNG 与 SVG 获取和解码成功，尺寸为 2×2。
禁用负例禁用三个 Coil 坐标后，Release 运行失败，原因是 Unable to create a fetcher；保留 OkHttp/Okio 规则以隔离 Coil 规则效果。
配置缓存与日志JVM runRelease 的配置缓存存储与复用通过；生成任务 UP-TO-DATE、ProGuard UP-TO-DATE 时仍输出逐依赖添加日志。KMP 配置缓存存储通过。
输入与禁用最终版本冲突、外部传递依赖、KMP desktop runtime、Compose 指定 SourceSet、插件顺序、可选禁用及空输出通过。
缓存恢复TestKit 验证 FROM-CACHE；外部 .pro 缺失或损坏时每次执行的校验步骤修复，不依赖 Gradle 守护进程的旧文件快照。
发布产物本地 Maven plugin marker、实现 JAR 和 POM 生成通过；独立消费构建按插件 ID + 0.1.0 从本地 Maven 仓库解析并成功生成规则和报告。

验证基线与规则修正

Gradle 8.14.3、Kotlin 2.2.0、Compose 1.9.3、ProGuard 7.7.0；插件与样例目标 JDK 17，运行 JDK 21。Coil 3.3.0、OkHttp 4.12.0、Okio JVM 3.15.0。

  • 仅保留 Coil 动态实现类不足以覆盖混淆：服务接口二进制名称也必须保留，确保服务文件路径仍有效。
  • OkHttp 可选平台/TLS 引用需要固定的定向警告规则；PublicSuffixDatabase 的资源相对路径需要保留名称。
  • 复现 Okio 多文件门面优化后的 VerifyError；定向禁止 okio.Okio__* 优化，同时保留 shrinking 和 obfuscation，未全包 keep。

交付与边界

源码仓库提供 README、spec、贡献规范、Apache-2.0 许可证、规则来源、Gradle Wrapper 校验哈希和跨平台 CI。当前源码接入方式为 pluginManagement.includeBuild；尚未发布到 Plugin Portal / Maven Central。

样例是无窗口的 Release 运行烟测；没有验证 GUI、原生安装包或消费业务项目。其他工具/依赖版本遵循已约定的最近规则选择策略，但不能据此声称均已运行验证。Compose 选中输入的适配涉及内部模型；自定义 fromFiles 输入明确不支持。
